# Languages: multilingual sites

**Always ask which languages the site will be built in**, even when the brief seems obvious. A local business in Montreal, Miami or Medellín often needs two languages. Ask it in the brief as a multi-select (English · French · Spanish · Other), then ask which one is the **default** (served at `/`) and whether every page exists in every language (usually yes; blog posts and legal pages can be the exception, but legal pages must exist in every language the site sells in).

Languages change the plan: the sitemap doubles or triples, headlines must fit the longest language, SEO keywords are researched per language, and legal pages are written per language. Put the language decision in the plan (item "Languages").

## Structure (proven on the Dany Designs site)

- **Default language at the root, others under a prefix:** `/`, `/fr/`, `/es/`. Don't redirect by browser language; let people choose and remember it via the links.
- **One view per page, thin page files per language.** The page markup lives once in `src/views/<Page>.astro` and takes a `lang` prop; `src/pages/index.astro`, `src/pages/fr/index.astro`, `src/pages/es/index.astro` are one-liners (`<Home lang="fr" />`). Dynamic routes (`[slug].astro`) do the same inside `getStaticPaths`.
- **Strings in one dictionary:** `src/lib/i18n.ts` exports `dict = { en, fr, es }` and `useT(lang)`. The English object is the type; the others must match it (`typeof en`), so a missing key fails the build.
- **Content with translatable fields:** in `content.ts`, fields that change by language become `{ en, fr, es }` objects, read through a helper. Numbers, images and slugs stay shared.
- **URL helper:** `url(path, lang)` builds `/fr/path` etc. Every internal link goes through it; a hard-coded `/contact` on a French page is a bug.
- **Slugs:** keep the English slugs in every language unless the SEO brief asks for translated slugs (then keep a slug map per page and use it in `url()` and the switcher).

## Required per page

- `<html lang="…">` set from the page's language.
- `<link rel="alternate" hreflang="xx">` for every language, plus `hreflang="x-default"` pointing at the default language. Each language version's canonical points at itself, never at the English page.
- `og:locale` and `og:locale:alternate`.
- A **language switcher** in the nav (and footer) that goes to the **same page** in the other language, not to the other home page. Label it with the language's own name ("Français", "Español"), not a flag.
- Title and meta description written in that language (not translated word for word; see SEO).
- JSON-LD `inLanguage` / `knowsLanguage` where relevant.

## Writing, not translating

- **Transcreate headlines.** A headline that works in English often lands flat when translated literally. Rewrite it in the target language with the same idea and rhythm (example: the FR eCommerce headline became "Fluide. Évolutif. Rentable."). Run `humanizer` on each language.
- Use local conventions: currency and number formats (`Intl.NumberFormat(lang)`), dates, phone formats, addresses, "tu"/"vous" and "tú"/"usted" chosen deliberately for the brand and used consistently.
- Form labels, validation messages, success states, 404, cookie banner and emails the form sends must all be translated. Nothing English should appear on a French page (grep for it).
- If the user speaks the language, ask them to review key headlines; otherwise flag the copy as needing a native review before launch.
- Helpful skills: `searchfit-seo:content-translation` (keywords + hreflang), `anthropic-skills:website-translator` if available.

## Design for the longest language

- French and Spanish run about 15–30% longer than English (German more). Design and test with the longest one.
- Headlines must never be cut off or overflow. Use fluid sizes (`clamp()`), `text-wrap: balance`, `overflow-wrap: break-word` and `hyphens: auto` with the right `lang`. Check process step titles, buttons, nav and pills specifically: they're where cut-offs happened before.
- Buttons and pills grow with their text (no fixed widths).
- Check each language at 375px width before calling a page done.

## Verify

- Every page builds in every language; `dist/` has the expected folders.
- Switcher on every page lands on the equivalent page.
- hreflang set is complete and reciprocal on each page (view source).
- Grep the other-language builds for leftover English strings from the dictionary's English values.
- Sitemap includes every language version.
